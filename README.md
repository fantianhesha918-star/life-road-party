# アニマルライフ(旧ライフロード)

人生ゲーム風のマルチプレイすごろくアプリ。盤面・カード・ルールはすべてオリジナル(市販の「人生ゲーム」の商標・盤面は使用していない)。リポジトリ名・公開URLは旧名称`life-road-party`のまま据え置いている(アプリ内表示名のみ「アニマルライフ」に変更)。

- 公開URL: https://fantianhesha918-star.github.io/life-road-party/
- 公開元フォルダ: `docs/`(GitHub Pages)
- ビルド不要。`docs/`配下を直接編集して`git push`すれば反映される。
- Firebaseプロジェクト: `life-road-party`(Firestore + 匿名認証、リージョン`asia-northeast1`)

## 現在の状態(フェーズ2・3: 通信モード動作確認済み)

- 一人モード(CPU対戦)・通信モード(部屋番号で友達と接続)ともに動作確認済み。
- Firestoreセキュリティルール(`firestore.rules`)は、本番のFirebaseプロジェクトに対するREST APIテスト(部屋作成・参加・不正書き込み拒否・手番制御・ハートビートの8パターン)と、実機(スマホ2端末)での通信対戦の両方で動作確認済み(2026-08-03)。
- **TTLポリシー(部屋の自動削除)は見送り**: 403エラーの原因はプロジェクトの権限反映待ちではなく、「TTL機能の利用にはBlazeプラン(課金プラン、要クレジットカード登録)への切り替えが必須」という仕様だった。本プロジェクトは無料枠のみで運用する方針のため、Sparkプランのまま据え置き、TTLは設定しないことに決定(2026-08-03)。そのため`rooms`コレクションの部屋データは自動削除されず残り続けるが、1部屋あたりのデータ量が小さく友人数人規模の利用なので実質的な問題にはならない見込み。放置データが気になる場合は、Firestoreコンソールから手動で古い部屋を削除できる。

## アバター・コイン・ショップ機能

- プレイヤープロフィール(コイン・所持アイテム・装備中の動物種/色/帽子/アクセサリー・消耗品の所持数)は**端末のlocalStorageにのみ保存**(Firebaseには送らない)。各プレイヤーは自分のスマホで遊ぶ想定のため、端末ごとにコイン・アイテムが独立して蓄積されていく。
- 対局終了時、最終所持金に応じてコインを獲得する(10万円につき1コイン、`shop-data.js`の`GAME_REWARD_MONEY_PER_COIN`で調整可能)。
- 獲得コインでショップ(色・帽子・アクセサリー・消耗品)を購入し、キャラクター編集画面で装備できる。
- **動物の種類**: チンチラ(グレー・白パイド)、いぬ(フレンチブルドッグ白・黒)、ねこ(三毛猫)、うさぎ(白)の6種類から選べる(`shop-data.js`の`SPECIES_ITEMS`)。6種すべて最初から無料で所持・切替え可能。実イラストは未準備のため、現状は絵文字で代用表示している(準備でき次第Codexに素材作成を依頼し差し替え予定)。動物種ごとに専用コスチュームを作る構想もあるが、それはイラスト準備後の対応で、現状の帽子・アクセサリーは種を問わず共通のまま。
- 通信モードでは、部屋を作成/参加する瞬間の「装備中の見た目」だけを部屋データに含めて送るため、コイン・所持アイテム自体は非公開のまま、対戦相手にはコスチュームだけが見える。

## ターン進行(ルーレット・ターンハブ・消耗品)

- サイコロ(1〜6)を廃止し、ルーレット(1〜10のランダム)に変更した(`game-engine.js`の`rollDice()`)。
- 自分の手番になると、アバターがポップインするターンハブ画面が表示され、「ルーレットを回す」「アイテムを使う」「ステータスを見る」の3択から選べる。ルーレットを回すと1〜10の数字が連続表示されるスピン演出のあと出目が確定する。
- 「アイテムを使う」では、ショップで購入した消耗品(臨時収入チケット・幸運のお守り・節税シールなど)を使って即座に所持金を増やせる(手番は終了しない)。消耗品はコスメアイテムと違い何個でも購入・重複所持できる。
- 盤面はマス数の制限をなくすため、1画面に収めず横スクロール式にした。手番プレイヤーがルーレットの出目ぶんマスをひとつずつホップ移動するアニメーションに合わせて、盤面表示も自動でその位置へスクロール追従する(`app.js`の`runHopSteps`/`scrollBoardIfNeeded`)。通信モードでは、この演出は「自分の手番を自分の画面で見ているとき」だけ再生され、相手の手番の移動は最終確定後の位置のみ相手側の画面に反映される(Firestoreは最終状態のみを同期するため)。

## CPU AIの性格プリセット

- 一人モードのCPUプレイヤーには、ゲーム開始時に3種類の性格プリセットからランダムで1つ割り当てられる(`cpu.js`の`CPU_PERSONALITIES`)。プレイヤーリストに「CPU1(CPU・野心家)」のように表示される。
  - 野心家: 就職の選択肢のうち給料が高い方を選ぶ(従来のCPU挙動と同じ)
  - 堅実家: 給料が控えめな方を選ぶ
  - 気まぐれ屋: ランダムに選ぶ
- 現状、性格が影響するのは就職の選択のみ(ゲーム内に他のCPU意思決定ポイントが無いため)。株・保険など新しいギミックを追加する際は、性格ごとの傾向をそちらにも反映できる。
- 通信モードはCPU非対応のため、この機能は一人モードのみに適用される。

## 盤面の3D化(検証段階・フェーズB進行中)

- 将来的に、盤面を「曲がり道や橋のある人生ゲームの実物のような3D空間」にし、キャラクターも本物の3D(マリオオデッセイのようなポリゴンモデルのリアルタイム描画)にする構想がある。無料のThree.js(CDN経由、ビルド不要)+無料CC0の低ポリ動物モデルを使う方針で、Codexが作れるのはイラストのみ(3Dモデル自体は作れない)ため、素材は別途無料配布元(**大手が運営する定番サイトのみ**: Kenney.nl・Adobe公式Mixamo・Quaternius公式サイト)から探して当てはめる想定。
- タイトル画面の「🧪3D盤面テスト(開発用)」ボタンから、直線パス上をホップ移動しカメラがズームイン追従するデモが確認できる(`docs/board3d.js`)。実際のプレイ(通常のゲーム画面)には一切影響しない、独立した検証用オーバーレイ。
- **Kenney.nl(CC0)の「Cube Pets」パックに犬・猫・うさぎ・ビーバー(チンチラ代替候補)の4種の3Dモデルが揃っていることを確認し、犬モデル(`docs/models/animal-dog.glb`)を実際に読み込んで表示するところまで実装済み**。スケール・接地位置は暫定値で実機確認後に調整予定。
- 曲がり道や橋のあるマップレイアウト・残り5種のモデル展開・色/柄のマテリアル塗り替え・通信対戦での3D表示は未着手(フェーズB継続〜フェーズC)。スマホ実機での見た目・動作確認を経てから、次に進める内容を判断する。
